# Threat model

Scope: a single user (Parth) running Jonathon on a personal Windows machine, bound to loopback. Assets: client
documents, derived knowledge, approval integrity, credentials (session, MCP tokens, the model provider sign-in held by
`agy`), and the host itself.

Trust boundaries:

1. Browser ↔ API (cookie session).
2. Claude Code ↔ MCP (bearer token).
3. API/worker ↔ data root and SQLite.
4. Worker ↔ `agy` process ↔ model provider.
5. Uploaded client content, which is untrusted data everywhere.

| # | Threat | Mitigations | Residual risk / tests |
|---|---|---|---|
| 1 | **Cross-project leakage** | Every service call takes an explicit `projectId` and a principal. `requireProject()` authorizes, and every SQL statement filters by `project_id` (FTS rows carry `project_id`). Runtime workspaces are per project. MCP tokens list their projects, and an out-of-scope project is reported as `PROJECT_NOT_FOUND`. Model-requested retrieval keeps the original project. | Tests: services "1.", server "only exposes authorized projects". |
| 2 | **Prompt injection** in documents | Evidence is fenced in tagged blocks. Tags inside client text are neutralised (`fence()`), so the model sees a block it cannot close. The system prompt says block content is data. More importantly, the runtime **has no tools** (agent `tools: [finish]`) and session deny rules forbid commands, files, URLs and MCP, so an injected instruction has nothing to act with. Outputs are only drafts or answers, and only a human can approve. | A model can still be misled in its *answer text*. Citations, verbatim quote checks, authority labels and human approval limit the impact. Live test: an injected "say 1 hour" was not followed (1 run, not a guarantee). |
| 3 | **Instruction-file loading** (`AGENTS.md`, `GEMINI.md`, `.agents/`) | Verified live: `agy` loads workspace `AGENTS.md` as rules. Client files are never written to runtime workspaces; originals live under `projects/…/sources/<id>/<rev>/original.<ext>` (the original filename is metadata only). `prepareWorkspace()` deletes anything except Jonathon's two agent files before each run. | **Global** rules (`~/.gemini/GEMINI.md`, `~/.gemini/config/rules`) still load into every run; `pnpm run doctor` and the Setup page report them. None exist on this host today. |
| 4 | **Shell injection** | `spawn()` with an argument array and `shell: false`. The prompt goes over stdin as JSON, never argv. The only argv values are fixed flags and Jonathon-generated paths and UUIDs (the conversation ID is validated as a UUID). `scripts/dev.mjs` uses a shell only for fixed literals on Windows. | Test: the runtime test asserts the prompt is absent from argv. |
| 5 | **Path traversal / encoded traversal / absolute paths** | Paths are built only from generated IDs and fixed names. `assertSafeSegment` allows `[A-Za-z0-9._-]` only and rejects `..`, `%`, separators, drive colons, NUL, leading dots and Windows device names. `resolveInside` re-checks containment. | Test: storage "path safety". |
| 6 | **Symlink / junction escape** | `resolveInside` uses `lstat` on every existing component and compares real paths. Workspace cleanup refuses symlinked entries. | Application checks are not atomic with the later file operation (TOCTOU). Someone with write access to the data root is already trusted. Test: junction escape. |
| 7 | **Parser attacks** (zip bombs, malformed PDFs, huge sheets) | Parsers run in a **worker thread** with a heap limit and wall-clock timeout. Zip entry count and uncompressed size are checked before Office parsing. Macro-bearing formats (`.docm`, `.xlsm`, `vbaProject.bin`) are refused. Formulas are not evaluated (cached values only, with a warning). HTML scripts, styles, iframes and images are dropped, and nothing is fetched. pdf.js runs without font faces. | Native code bugs inside dependencies remain a risk. Dependencies are pinned and installed with a 7-day minimum release age. |
| 8 | **Oversized uploads** | `JONATHON_MAX_UPLOAD_MB` is enforced by multipart limits and the service. JSON bodies are capped at 4 MB. Prompt size is capped by `AGY_MAX_PROMPT_CHARS`, and runtime stdout by `AGY_MAX_OUTPUT_BYTES`. | |
| 9 | **Stored XSS / unsafe Markdown** | The UI never uses `dangerouslySetInnerHTML`. A small Markdown renderer builds React elements, so HTML in model or client text shows as text, and links are not rendered. Originals are served only as `application/octet-stream` with `Content-Disposition: attachment`, `nosniff`, and a sandbox CSP. The web CSP has no third-party origins and `frame-ancestors 'none'`. | The dev CSP allows `unsafe-eval` for Next.js dev only. |
| 10 | **Credential leakage** | Passwords use scrypt. Session and MCP tokens are stored as SHA-256 hashes and shown once. pino redacts auth headers, cookies, tokens, passwords, text and prompts. The runtime gets a **scrubbed environment** (system variables plus agy's own auth variables only, never `JONATHON_*`). Error responses for `INTERNAL` hide details. | Antigravity's own credentials live in the OS keyring under agy's control. |
| 11 | **Unauthorized approval** | `approve`, `reject`, `supersede`, `resolve` and `answer` require `principal.kind === "user"` and a typed confirmation. MCP has no approval tool, MCP scopes are only `read` and `propose`, and the worker is a `system` principal that cannot approve. Approval events bind to revision plus semantic hash, so a typed `status: approved` in a file is not an approval, and editing approved content revokes it. | Tests: storage "approval requires a human…", "manually typed status", "external edits"; services "9-10". |
| 12 | **CSRF** | `SameSite=Strict`, `HttpOnly` session cookie. Every cookie-authenticated mutation requires `X-CSRF-Token` equal to the session's token. Origin and `Sec-Fetch-Site: cross-site` are checked. | Test: server "requires CSRF". |
| 13 | **DNS rebinding / invalid Host or Origin** | Host must be one of `127.0.0.1:<port>`, `localhost:<port>`, `[::1]:<port>` or a configured web origin host. A foreign `Origin` (or `null`) is rejected, and this also covers `/mcp`. The server binds to loopback and refuses a non-loopback host unless `JONATHON_ALLOW_REMOTE=true`. | Test: server "rejects invalid Host". |
| 14 | **Model-triggered data exfiltration** | The model has no tools (no web search, URL fetch, shell or MCP), which was verified live with the `tools: [finish]` agent. Deny rules are a second layer. The stream guard kills the process tree if any tool step starts. | **The text the model receives is sent to the model provider by design**, and that is disclosed in Setup. Without the custom agent, `search_web` is *not* covered by deny rules (verified), which is why the agent restriction is mandatory and checked via `init.agent`. |
| 15 | **Session crossover** (runtime conversations) | Runtime sessions are mapped explicitly by (project, Jonathon conversation, owner, config hash). A provider conversation ID can be stored only once (unique index). `--continue` is never used. If `agy` silently starts a new conversation for a lost ID, Jonathon detects it and flags `context_rebuilt`. Turns in a conversation are serialized by job `serial_key`. | Tests: services "follow-ups reuse…", runtime "silently replaced". |
| 16 | **Exit 0 masquerading as success** | Success requires `status: SUCCESS`, exit 0, no denials (`denied_actions`, deny-rule tool errors, stderr auto-deny notices), no tool steps, the expected agent and permission mode, and schema-valid `structured_output`. Anything else is a typed error, and no answer is stored. | Tests: runtime "denied", "soft-denied", "tool-attempt"; services "7.". |
| 17 | **Data retention outside Jonathon** | Disclosed in Setup and on the delete screen: `agy` keeps transcripts under `~/.gemini/antigravity-cli/`, and the provider has its own retention. Jonathon cannot delete either. | |
| 18 | **Encryption at rest** | **Not implemented.** Files and SQLite are plaintext. Use BitLocker or equivalent. Backups are also plaintext. | Documented here and in the UI. |
| 19 | **Client documents in Git** | The data root defaults to `%LOCALAPPDATA%\Jonathon`, and Jonathon refuses a data root inside the repository. `.gitignore` excludes `data/`, `.env`, `*.sqlite`. There is no Git versioning of client data. | |

## Known gaps

* The stream guard reacts after a `tool` event. Prevention relies on the agent tool list and deny rules (both verified on 1.5.9).
  A future `agy` version could change that behaviour. `pnpm run doctor` warns when the version differs from 1.5.9, and `pnpm test:live` re-verifies it.
* Single-user design: there are no roles beyond the local account and MCP token scopes.
* No rate limiting beyond login lockout and bounded worker concurrency.
